# Publication boundaries

- Keep this repository organization-neutral and use synthetic demo data.
- Treat private source documents and conversations as confidential inputs. Do not commit, upload, quote, paraphrase or summarize their organization-specific findings here, in pull requests, issues, workflow logs, or distributable assets.
- Protect against indirect identification: do not publish combinations of job title, employer, location, event, quotation, or opinion that could identify a source person. Replacing a name alone is insufficient.
- Implement agreed general capabilities without embedding confidential evidence, named real pilots, internal organizational assessments, or source-report mappings.
- Do not copy external reports, transcripts, private prompts, or audit backups into this repository or build output.
- Preserve repository visibility. Never make a private repository public to resolve deployment limitations.
- A public deployment requires a separate review of both the source changes and generated assets. An unlinked file in public/ is still published.
- Existing historical material is not authorization to republish it. Keep incident findings and cleanup backups outside public GitHub surfaces.
